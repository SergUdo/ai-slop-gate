## 🏗️ Architecture

### System Flow

1. **Developer** pushes code to repository
2. **Version Control System** (GitLab/GitHub) triggers CI/CD pipeline
3. **Adapter Layer** processes the changes:
   - Maps MR/PR metadata to Core Engine
   - Fetches code diffs and changes
4. **Core Engine** runs comprehensive analysis:
   - **AI Slop Detection** - identifies AI-generated code patterns
   - **Static Analysis / Linting** - checks code quality and style
   - **Security Checks** - scans for vulnerabilities and secrets
   - **LLM Multi-Model Logic Scan** - deep semantic analysis using multiple AI models
5. **Reporter** delivers results:
   - Adds detailed comments to MR/PR with findings
   - Sets pipeline status: `PASS` / `WARN` / `FAIL`
6. **CI/CD Pipeline** receives exit code and blocks or allows merge based on policy

### Key Components

- **Adapter Layer**: Abstracts GitLab/GitHub specifics, providing unified interface to Core Engine
- **Core Engine**: Policy-driven analysis engine with pluggable providers
- **Reporter**: Formats and delivers results to appropriate channels (console, PR comments, MR notes)

## Execution Model

### High-level Flow

1. CLI parses flags  
2. Policy is loaded and resolved  
3. Providers collect observations  
4. Compliance sidecar optionally runs  
5. Policy engine evaluates observations  
6. Decision is produced  
7. Reporters render output  
8. Exit code is derived from decision
